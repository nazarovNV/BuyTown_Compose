# UI-тесты BuyTown

Все основные пользовательские сценарии находятся в пакете `com.example.buytowncompose.ui`. Тесты запускают настоящий интерфейс. Для работы не нужен сервер.

## Запуск с наблюдением

1. Запустите эмулятор в Android Studio → Device Manager и дождитесь домашнего экрана Android.
2. Откройте терминал в корне проекта.
3. Выполните:

```powershell
.\scripts\Run-UiTests.ps1 -DelayMs 500
```

Скрипт соберёт приложение и тестовый APK, установит их и запустит тесты. Смотрите на эмулятор: ввод, нажатия, переходы и поворот Activity выполняются автоматически. `DelayMs` добавляет паузу после действий только для визуального наблюдения. Без этого параметра тесты работают быстрее.

```powershell
# Полный набор без замедления
.\scripts\Run-UiTests.ps1

# Один раздел
.\scripts\Run-UiTests.ps1 -TestClass CartUiTest -DelayMs 500

# Один тест
.\scripts\Run-UiTests.ps1 -TestClass 'AuthUiTest#wrongPasswordCanBeCorrected' -DelayMs 700

# Повторный запуск уже собранных APK
.\scripts\Run-UiTests.ps1 -NoBuild -TestClass CatalogUiTest

# Если подключено несколько устройств
.\scripts\Run-UiTests.ps1 -Device emulator-5554
```

Скрипт берёт JDK из `.gradle/config.properties`, SDK — из `local.properties`. При необходимости JDK можно указать через `-JavaHome 'D:/PyCharm 2025.2.3/jbr'`.

Скрипт возвращает ошибку, если сборка, установка или тесты не завершились успешно. Результаты последнего запуска находятся в `app/build/reports/ui-tests/index.html` и `latest.log`. Он использует AndroidJUnitRunner напрямую, без дополнительной загрузки плагинов UTP.

## Запуск из Android Studio

В дереве проекта откройте `app/src/androidTest/java/com/example/buytowncompose/ui`, нажмите правой кнопкой на пакет и выберите **Run 'Tests in ...ui'**. Можно запускать отдельный класс или метод зелёным треугольником рядом с ним. Выберите эмулятор как целевое устройство. Результаты будут в окне Run.

Для замедления добавьте в конфигурации Android Instrumented Tests аргумент instrumentation: `demoDelayMs=500`. На компонентные тесты `ScreenStateUiTest` эта задержка не распространяется.

Стандартный запуск через Gradle тоже доступен:

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest '-Pandroid.testInstrumentationRunnerArguments.package=com.example.buytowncompose.ui'
```

Он создаёт стандартный HTML-отчёт в `app/build/reports/androidTests/connected/debug`. При первом запуске может потребоваться интернет для компонентов Android Test Platform. Альтернативный скрипт выше не использует эту платформу.

## Покрытие

| Класс | Сценарии |
| --- | --- |
| `AuthUiTest` — 9 | Начальный экран, переключение форм, пустые поля, неверный пароль и его исправление, неизвестный аккаунт, несовпадающие пароли, занятый логин, регистрация и повторный вход после пересоздания Activity, demo-вход, системная кнопка назад |
| `CatalogUiTest` — 5 | Поиск без учёта регистра с пробелами, очистка, поиск по категории и описанию, отсутствие результатов, все 6 категорий, описание и характеристики товара, возврат к поиску, нижние вкладки и назад |
| `CartUiTest` — 7 | Пустая корзина, кнопка и счётчик, уменьшение до нуля, синхронизация карточки и сетки, несколько товаров и точная сумма, удаление, возврат из карточки в корзину, пересоздание Activity, изоляция между аккаунтами |
| `ProfileUiTest` — 4 | Валидация имени, сохранение имени и аватарки после повторного входа, все аватарки, сохранение черновика при пересоздании Activity, отдельный профиль для каждого аккаунта |
| `ScreenStateUiTest` — 4 | Блокировка формы при входе и загрузке профиля, отображение ошибки и обработчик повторной загрузки, блокировка плюса при 99 товарах |

Всего **29 UI-тестов**. Дополнительно сохранён полный сквозной сценарий `presentation/ShoppingFlowTest`, тесты ViewModel и локальных аккаунтов, а также модульные тесты.

Это покрытие сценариев текущего демо, а не заявление о 100% покрытии кода. Реальная сеть, оформление заказа, выбор фото из галереи и серверная сессия отсутствуют в приложении и здесь не тестируются. Пересоздание Activity проверяет смену конфигурации, а не убийство процесса Android.

## Изоляция и устойчивость

- Для каждого сценария создаются уникальные тестовые логины; после теста удаляются только их аккаунты и профили. Личные данные и существующие аккаунты не очищаются.
- Для demo проверяется только вход, профиль этого аккаунта не изменяется.
- У элементов добавлены стабильные `testTag`; они не меняют внешний вид или поведение.
- Тесты синхронизируются через Compose и ожидают завершения асинхронных операций через `waitUntil`. Произвольные паузы не используются для проверки корректности.
- Реальные репозитории используются в сценарных тестах. Кратковременные состояния загрузки и ошибки отдельно проверяются в `ScreenStateUiTest`.
- Каждый тест начинает с авторизации. Можно запускать отдельный метод и весь набор повторно.
